# Contributing to QUB

Thank you for your interest in contributing to the QUB specification.

## How to Contribute

### Reporting Issues

Use [GitHub Issues](../../issues) to:

- Report problems or ambiguities in the specification
- Suggest new track types or features
- Discuss NLE integration approaches
- Share implementation experiences

Please search existing issues before creating a new one.

### Proposing Changes

1. **Fork** the repository
2. **Create a branch** for your changes (`git checkout -b feature/my-proposal`)
3. **Make your changes** with clear commit messages
4. **Submit a Pull Request** with a description of:
   - What you're changing
   - Why the change is needed
   - Any compatibility considerations

### What We're Looking For

**High Priority:**

- Track type definitions — Are we missing critical AI outputs?
- NLE integration details — What does your actual workflow need?
- Professional codec support — Edge cases, broadcast formats
- Security model feedback — Encryption, privacy levels, redaction approaches

**Also Welcome:**

- Typo fixes and clarifications
- Example data structures
- Implementation notes from prototyping
- References to related standards or prior art

### Specification Change Process

1. **Discussion** — Open an issue describing the proposed change
2. **Feedback** — Community and maintainer input
3. **Draft** — Submit PR with spec changes
4. **Review** — Technical review for correctness and compatibility
5. **Merge** — Changes incorporated into next spec version

Breaking changes require:
- Strong justification
- Migration path documentation
- Version number increment

### Code of Conduct

Be respectful. We're all here to build something useful for creators.

- Assume good faith
- Focus on technical merit
- Welcome newcomers
- Keep discussions constructive

### Licensing

By contributing, you agree that your contributions will be licensed under the Apache License 2.0.

## Questions?

Open an issue tagged `question` and we'll do our best to help.
